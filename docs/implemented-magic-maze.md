# Magic Maze：2017 出版商 PnP 试玩版

核验日期：2026-09-16。`src/games/magic-maze.ts` 导出 `magicMaze`。唯一场景为 `pnp-2017-discovery`，支持 1–8 人。

## 版本与资料

依据 [出版商制作的完整 Print & Play PDF，Ludovox 托管](https://ludovox.fr/wp-content/uploads/ressources/MM_Print%26Play.pdf)。11 页文档每页标明作者 Kasper Lapp、美术 Gyom、出版商 Sit Down!；正文说正式游戏将在 2017 年 2 月发行，美术带有 WORK IN PROGRESS 水印，因此明确标识为 2017 发行前试玩版，不冒充零售版最新规则。

文件包含此试玩关卡的全部组件：九张地图、一张盗取标记双面、四个沙漏使用标记、十九张适用于各人数的行动卡。棋子为红、黄、绿、蓝四色，共用一个出口。角色只是不同颜色的棋子；没有 RPG 扮演、成长或主持机制。

## 统一接口和流程

```text
setup(pnp-2017-discovery, 1..8, seed)
  → briefing：全部地图规则可查询；初始棋盘公开；message / ready
  → 全员 ready：开始三分钟沙漏
  → playing：所有玩家同时有行动权，按各自卡牌权限行动
      move / explore / teleport / escalator / signal
      单人另有 reveal_action
  → 进入未使用的沙漏格：强制翻转，进入 discussing
      message；时间继续流逝；首个游戏行动恢复 playing
  → 四棋子同时在各自物品格：自动盗取，永久禁用传送
  → 四棋子均从共同出口离开：胜利
  → 任意时刻沙漏归零：失败
```

没有轮流发言十次或强制讨论内容。初始 `ready` 只是数字接口结束自由准备时间的协议。多人随时可以行动，不把游戏改成轮流游戏；服务用原子事务处理同时送达的请求，以避免两人同时移动同一棋子。

示例：

```json
{"type":"move","hero":"red","direction":"N","distance":2}
{"type":"explore","hero":"blue"}
{"type":"teleport","hero":"green","x":0,"y":3}
{"type":"escalator","hero":"red"}
{"type":"signal","target":"p2"}
{"type":"reveal_action"}
```

`explore` 一次完成揭示顶图、旋转并连接。按这份试玩规则第 4 页，将白箭头接到发起探索的英雄位置；不从零售版额外借入“揭图后再选另一出口”的选项。所有图的入口和外接矩形一致，合法性判断不依赖未揭示图身份。探索后通道可由任意颜色英雄双向通过。

四人同时到达对应物品即刻触发盗取，没有可拖延的 `steal` 操作。共同出口在盗取后的逃跑阶段才移除棋子；试玩正文没有“提前踩出口立即失败”的条款，因此没有从零售版混入该失败判定。

## 时间、状态和信息

`advanceTime(state, elapsedMs)` 是可信运行器专用方法，不能由玩家 API 提供时间。服务需要在读取和行动前推进实际经过的毫秒；纯本地运行器也必须明确注入时间。暂停或零时间实验只能标为研究运行，不能和官方限时玩法混为一谈。

设沙漏总长为 `180000 ms`，翻转前还剩 `r`，翻转后剩余时间为 `180000-r`。提前翻转可能减少时间；每个沙漏格仅生效一次。讨论期间时间不会暂停。到零即输，不能在已经超时后用移动补救。

`decisionContext` 与观察基本相同，只删除持续变化的 `remainingMs` 和 `elapsedMs`。棋子、地图、权限、沟通阶段和终局仍参与决策身份：纯倒计时不会让已经在发送途中的动作立即过期，棋局或胜负改变则会。

`observe` 给完整已知地图、各人公开行动卡、棋子与公开动作，但不会给未揭示地图顺序、未翻单人行动牌顺序或 RNG。单人已揭示行动保留在事件历史中，可依规则记忆。`legalActions.examples` 枚举当下可执行动作，不做策略指导。拒绝动作不改变输入；状态可直接 JSON 序列化。

多人“盯着别人看”和“把 Do Something 棋子放在别人面前”统一表达为无附加文本的 `signal{target}`。正式聊天只在准备期和沙漏讨论期可用；这些时期没有额外的牌面语义限制。因此本版机器验证器是 `exact`，指该接口内的规则与胜负验证，不证明玩家没有在工具之外私聊，也不模拟表情和手势。

## 验证

`node --test test/magic-maze.test.ts`：18 项通过。覆盖所有组件计数、九张图内部连通性、1–8 人权限组合、四方向旋转探索、不同色英雄过探索口、隐藏信息不变性、墙与棋子阻挡、地图 5 的两道易漏墙、传送、电梯、全部沙漏格、时间归零、决策上下文、自动盗取、出口、单人回收与洗牌。另有八种人数的合法动作加可信时间运行，均可到终局。

另有三人、固定种子的完整可达性验证：从正常开局经过 168 次实际动作，探索九张图、集齐物品自动盗取、四人从共同出口逃离，并对动作/时间全部重放。路径搜索只使用公开地图和棋子位置，动作由相应权限玩家经 `step` 执行，不改写地图、起始棋子或阶段。每动作只注入 1ms 模拟时间，因此它证明规则流程与地图可达性，不是限时智能体胜率。

其余边界成功局面是明确构造的规则测试，也不能当作智能体完整获胜轨迹。没有声称完成零售 24 图、后续场景、人物能力或扩展。
