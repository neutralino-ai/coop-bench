# 进行中行动者、倒计时和轨迹空间

用户报告 p2 已行动、p3 掉线等待时回放仍高亮 p2。旧实现按最新记录的 playerId 高亮，同时统一使用该动作之前的状态。

0.11.3 在进行中且选中最新位置时使用该帧记录的最新 views，由 control.required 决定当前行动者；早期无 control 记录才回退到游戏可见的 current 字段。牌面、高亮与截止时间使用同一时点。历史步骤继续使用动作前信息、所选动作的行动者。实时倒计时只在最新位置显示，使用服务端 deadlineAt / episodeDeadlineAt 与 HTTP Date 校正时钟，不自行执行动作；结束或浏览历史时隐藏。

Agent 轨迹取消底部重复动作栏，行动及理由仍在轨迹卡内；轨迹区占满剩余高度。手牌、提示标题与审计入口并排，移除重复说明及“跳到这一步”。人类理由解除固定行数截断，允许在可用高度内滚动。

本地107项测试、Windows开发态123项通过。1440×900与1280×800实际窗口截图已检查，页面及时间线无溢出。1280×800下 Agent 决策区由约168px增至229px。新增实际窗口验收覆盖p2完成后p3高亮、倒计时递减、历史时点高亮和计时器隐藏。

私有 server/artifacts/replay-live-regression.ts 使用隔离 PostgreSQL 和真实花火规则执行 p1、p2 合法动作。验证最新记录的行动者为p2，而实时回放高亮p3，剩余预算约180秒；历史步骤高亮p1，结束后选中p2动作仍高亮p2。未访问生产对局。包含独立验证过的手机开局 HTTP400 修复，见 ios-game-entry-delivery-2026-09-22.md。
