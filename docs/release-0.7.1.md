# Coop Bench 0.7.1

包含 0.7.0 的游戏规则入口、花火提示计数、密码输入诊断与 GitHub 更新功能，并修复真实 GitHub 安装包下载失败。

## 安装

旧客户端请手动下载并安装本版本：Windows x64 使用 `.exe`；Mac Apple Silicon 使用 `mac-arm64.dmg`，Intel 使用 `mac-x64.dmg`。安装后，“设置 → 检查更新”会按当前系统选择新版本，下载、校验 SHA-256，再由用户打开安装器。

0.7.0 的更新检查正常，但远程模式下载遇到 HTTP 302 会失败，因此从 0.7.0 升级也需手动下载安装器。不要重新安装 0.7.0。

## 下载修复与验证

真实 GitHub 下载验收发现 Electron `session.fetch` 的手动重定向模式会拒绝下载跳转。更新通道改用 Node 标准 `fetch`；游戏 API 继续使用原通道。固定仓库、HTTPS、GitHub 下载主机限制、重定向次数、超时、文件大小及 SHA-256 校验均保留，不关闭 TLS 校验。

包内 smoke 现在通过应用实际使用的网络栈访问本机合成 HTTP 服务，经历真实 302 后才接收文件，覆盖之前只返回合成 `Response` 漏掉的行为。修复后的通道也已匿名读取真实 GitHub Release 并下载 Windows 安装器，字节数和摘要一致；验收不执行真实安装器。

Windows 本机：299 项自动测试、37 项包内远程客户端检查、14 项包内单机检查通过。版本标签须在 Windows x64、Mac Intel、Mac Apple Silicon 的原生构建及包内验收全部通过后才发布。当前安装器仍未签名，Mac 未公证，真实 Mac 的安装和系统安全提示不包含在 CI 自动验收中。

## 登录排查

用户报告 Windows 0.6.0 设置密码后，Mac 0.5.0 用同一 API 登录失败。两版的密码提交和主进程认证代码一致，未发现密码协议不兼容。密码保存在服务器，与设置密码的设备无关。

已验证：安装中的 0.6.0 认证模块设置合成密码后，具有独立空白配置的新版客户端能登录；两客户端各持独立会话，退出一端不会注销另一端。此流程也已加入自动测试。测试包含中文、全角字符和首尾空格，密码不被裁剪或归一化。

生产检查仅确认密码已保存、账号正常、后续登录收到认证拒绝，尚未证明用户实际失败的根因。没有读取或重置用户密码。新界面提供“显示密码”、Caps Lock / 首尾空格 / 全角字符提醒，须在用户 Mac 上核对实际登录。

## 游戏界面

- 顶部“游戏规则”可查看规则概要、场景、实现范围与来源。
- 花火显示全队“剩余提示 x / 8”，提示消耗 1，弃牌或成功打出 5 恢复 1。显示对应选中的历史时点。游戏引擎原本已经执行这些限制。
- 保持三人一屏的手牌、可见信息、思考记录和动作；完整原文在弹窗中查看。

公开源码和安装包不包含生产凭证与轨迹，API 仍需登录。本次未修改生产引擎、密码或数据。其他功能和规则来源见 [0.7.0 说明](release-0.7.0.md)。
