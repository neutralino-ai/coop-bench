# Coop Bench 0.7.2：加载状态与回放按需读取

打开回放时先展示牌局，后台读取当前步骤相关玩家的消息。启动有本地加载页；切换对局有文字、骨架占位和等待时间，失败后可重试。遵循系统“减少动态效果”设置，该设置开启时使用静态加载标识。

## 为什么上一版慢

2026-09-18 对既有 23 分花火对局只读测量：

| 内容 | JSON 字节数 | 用途 |
| --- | ---: | --- |
| 62 帧回放 | 1,174,929 | 精确动作输入、历史玩家视角、动作、审阅和规则元数据 |
| 372 条原始消息 | 1,332,103 | 各玩家实际提交的输入、输出和工具消息 |

回放约 1.12 MB 用于各步的 `observed` 与 `views`，其中含重复的观察结构和合法动作说明。当前接口仍返回完整回放 JSON，不是按帧分页或差分协议，也未启用该响应的网络压缩。附件文件一直是点击后下载，初始加载慢并非下载了全部附件。

0.7.1 在打开时自动读取每位玩家的消息，六页之间固定等待 3.1 秒，共约 15.5 秒；还额外读取原始消息查看器的第一页。局面本可先使用，但消息就绪很慢，读取牌局时也没有明确占位。

## 变化与边界

- 静态启动页不依赖远端 API；脚本未正常初始化会保留错误 / 重试提示，窗口背景与界面一致。
- 回放下载期间显示占位，20 秒请求超时会给出明确错误；切换或退出取消旧请求，过时结果不能覆盖新对局。
- 牌局加载完成立即可回放；只为所选步骤中已经行动的玩家获取消息，复用本局已读页。当前接口只能按玩家分页，某一步的记录仍可能需要翻页查找；不会声称已实现服务器端逐步精确查询。
- “完整记录”打开后才读取原始消息查看器和附件清单。原始附件仍须点击下载。
- 消息读取允许小量立即请求，之后按额度补充；GET 遇到 429 最多等待并重试两次，连接变更或取消会终止重试。POST 不自动重试，避免重复创建对局。
- 每席复制配置包含 `gameId`、`scenarioId` 和 `playerId`，可直接交给读取 [PLAY.md](../PLAY.md) 的 Agent。
- 游戏核、云端数据库、历史轨迹、认证与访问权限没有修改；不是标准 MCP 发布。

## 验证

- 303 项自动测试通过，包括慢加载、旧响应、退出隔离、读取限流重试与禁止写入重试。
- Windows 0.7.2 开发版与实际打包程序通过 41 项隔离桌面检查，包内单机模式 14 项检查通过；加入慢响应和失败重试，检查首屏不预取无关玩家 / 附件 / 重复消息页。保留 1280×800 与 1440×900 一屏验收。
- 打包的 Windows UI、preload 和网络桥只读连接已有云端花火，实际首屏约 **1.92 秒**（含恢复登录、目录与回放下载）。首位玩家消息读取完成约 **5.63 秒**，其中一次 HTTP 429 自动等待约 3.2 秒后恢复。该次网络测量不是所有地区 / 设备的延迟保证；首屏可在消息读取期间操作。
- 原始结果在忽略目录 `artifacts/loading-tests.txt`、`artifacts/loading-packaged-check/` 和 `artifacts/replay-0.7.2-live-check/`；不提交真实对局内容或凭证。
- Mac Intel / Apple Silicon 由版本标签的原生 CI 构建与验证，发布只在三平台通过后进行。真实 Mac 安装、签名 / 公证仍不包含在此次 Windows 验收内。
