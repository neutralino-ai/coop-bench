# 人类花火页面：动作历史与提示知识

以下为开发阶段记录；这些客户端修改已进入桌面 0.9.6，正式发布与配套后端状态见 [交付记录](desktop-0.9.6-delivery-2026-09-21.md)。

## 问题与修复

原 Player 花火牌面分支仅在自己的未知牌上显示 possibleColors / possibleValues，队友牌面虽然收到同样字段，却没有渲染。原历史入口是折叠的 JSON，且仅展示最近一批 observation.updates。

现在每张牌分开显示真实可见牌面与牌主收到提示后剩余的颜色、数字范围。包括提示没有命中的牌所排除的可能；这不是队友的私有推理，也没有用真实牌面代替其提示知识。

动作历史在动作栏顶部直接展示，最新在前，可滚动查看。花火提示显示发起者、接收者、提示内容和命中的一基牌位；出牌、弃牌显示公开翻出的牌和出牌结果。原始本席观察和更新仍可展开。

运行器将本席 updates 的公开 lastEvent 按 seq 存入本席 SQLite visible_history 表。重复分页不重复插入；相同末次事件因终局等状态重发时不重复展示。历史显示独立于 observationId 更新，避免同一局面不同历史页被忽略。模型上下文确认不清除此显示记录。升级时从原 pendingUpdates 和最后 observation.updates 补入已有记录；普通人类会话此前未消费 pendingUpdates，因此可以恢复已接收历史。旧模型会话已经确认且不再保留于这些字段的历史不会凭空补齐。

## Agent 实际输入

花火服务端本席观测包含所有人的 possibleColors / possibleValues、其他人的真实牌面、公共局面、lastEvent，以及逐步的本席可见 updates。自己的真实牌面、未抽牌堆顺序、其他玩家私有推理和审计权限不在其中。

内置 MinimalAgent 每次接收尚未确认给模型的 updates，同时持久保留此前模型对话。外部 Agent 按自己的 wait 游标及分页协议读取、保存历史；接口提供数据不等于已验证某个外部 Agent 实际使用了数据。
