# 服务端 Rollout 与人类审计前端

## 分工

- **Agent 使用 HTTP API**：规则、自己的观察、沟通和动作，结束后可以提交自己的反思。
- **人使用首页**：查找对局、回看时间线、切换玩家视角、检查公开讨论和决策简述、记录审阅意见并导出数据。
- `/play` 保留原来的动作调试台，用于开发时检查接口。

默认服务是 `http://localhost:8788`，只监听 `127.0.0.1`。主页需要协调者凭证；桌面壳通过受控 IPC 自动连接，普通浏览器可从 `data/local-server/coordinator-token` 复制到登录框。凭证只保留在当前页面内存中，不放 URL 或浏览器本地存储。

本次审计台更新在源码与 localhost 服务交付。既有 `0.3.0` 安装包为此前构建；重新运行打包命令后，安装包才会包含本次更新。

## 自动保存，而不是赛后才导出

SQLite 是记录来源；无需让 agent 额外运行导出脚本。一次动作提交在同一个事务中保存规则状态、幂等回执、事件，以及对应的回放帧。正常重启后记录仍存在。

| 数据 | 存储与含义 |
|---|---|
| 对局 | `episodes`：游戏、场景、原始引擎版本、状态与终止原因 |
| 事件 | `events`：服务端时间、玩家、接受/拒绝动作、错误、状态哈希 |
| 实际决策输入 | `observations` 与动作里的 observationId 关联，保存玩家动作明确引用的观察 |
| 回放帧 | `rollout_frames`：事件之后所有座位各自可见的视图、合法动作、终局结果 |
| 赛后材料 | `rollout_annotations`：反思/人类审阅意见、玩家归属、来源、服务器收到的时间 |

创建、接受、拒绝、时间推进和截断都会保存帧。对同一动作的幂等重试仍返回原回执，不制造第二次游戏动作。数据库写入失败时，动作和回放帧一同回滚。

审计读取不推进游戏、不新增玩家观察、不改奖励。实时游戏的经过时间仍由原服务端时钟机制在 agent 请求时结算；审计界面显示已经记录的时间状态。

## 信息边界

时间线区分两个问题：

1. **动作前输入**：该动作实际绑定的本人观察。它不能充当另一个玩家的决策输入。
2. **动作后视图**：当时服务端记录的每个玩家可见信息，不意味着每个 agent 当时都读取了它。

Take Time 棋盘显示六格、太阳/月亮牌、暗牌、本人手牌和已知总和。存在暗牌时显示未知，不将其当作0或用终局数值补齐。其他游戏通过通用的玩家状态卡、数组/字段视图和原始数据展开项审计。

管理员审计权限可看到多个玩家视图；这是一种人类审计权限，不是给玩家的工具。座位凭证不能访问 `/rollouts`。反思是结束后附加的说明，不能作为静默阶段的聊天通道。

## 旧记录与版本

升级前的对局没有完整 `rollout_frames`。界面使用已保存的动作前观察和动作回执，缺失的其他玩家视图显示“未记录”。不会用较晚手牌补齐，也不会改写原引擎版本。

旧版本的历史记录、审计和训练数据仍可读取。重新执行规则引擎的验证要求版本一致；版本不一致会返回 `BUILD_MISMATCH`。查看历史记录与证明当前版本重放一致是两件不同的事。

先前 Take Time 试玩的三份反思和两份审计意见通过协调者导入数据库，明确标记导入来源；不冒充座位新提交的反思。重复运行 `node scripts/import-demo-annotations.mjs` 会跳过相同内容。

## API

所有路径以 `/api/v1` 为前缀。

| 方法与路径 | 身份 | 功能 |
|---|---|---|
| `GET /rollouts?limit=50&offset=0&status=completed&gameId=take-time` | 协调者 | 分页、按状态/游戏筛选 |
| `GET /rollouts/:id` | 协调者 | 元数据、时间线、视图、证据来源、附加反思和审阅 |
| `POST /rollouts/:id/annotations` | 协调者 | 添加审阅或代录反思；不会改变游戏轨迹 |
| `POST /episodes/:id/reflections` | 本玩家座位 | 对局结束后追加自己的反思，身份由座位凭证决定 |
| `GET /episodes/:id/audit` | 协调者；结束后 | 完整特权原始记录 |
| `GET /episodes/:id/training` | 协调者；结束后 | 本人观察/动作、终止标签与团队奖励 |
| `GET /episodes/:id/replay` | 协调者；同版本且结束后 | 逐步重新执行并核对状态哈希 |

人类审阅：

```json
{"kind":"review","playerId":"p2","text":"第8手偏离了看牌前约定，需要进一步比较。"}
```

Agent 赛后反思：

```json
{"text":"这里写基于本人观察与终局结果的简短反思，区分当时信息与事后发现。"}
```

工具桥接也支持：

```text
node scripts/player-action.mjs PATH/TO/seat.json reflect PATH/TO/reflection.json
```

反思和审阅是追加记录，成功提交后不用再次提交相同文本。玩家请求不能指定另一个 playerId 或伪造来源；管理员代录和座位本人提交有不同标记。

## 训练用途

动作轨迹和审阅材料分开。`decisionSummary` 是当时随动作提交的简短理由，不是隐藏思维链；赛后反思也不能混入动作前输入。终局奖励为一局的标签，胜局不自动等于每个动作都适合专家 SFT。全局审计包含特权信息，不可直接用作玩家训练输入。
