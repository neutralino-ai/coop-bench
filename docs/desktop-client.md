# 桌面客户端

主客户端用于创建房间、加入人类对局和审计。0.9.2 打开显示密码登录，登录后直接进入房间与回放两个区块，“返回我的对局”恢复当前账号在此服务器保存的席位。参赛窗口只有本席权限，与审计窗口使用不同桥接。独立 Player 继续支持邀请和模型参赛，使用独立应用 ID 与本地凭据存储。0.9.1 起不包含游戏服务器，也不再支持内置单机模式。

在设置中选择组织者给定的完整 API 地址，保存后检查连接状态。旧地址 34935 与新地址 34936 的数据独立；相同域名不表示相同服务。新安装默认地址为 34936，已有保存设置继续优先。

管理端用账号密码或发放的个人凭据登录。设置已有密码需要当前密码；另一机器需连接同一服务并用同一账号登录。玩家 seat token 不能作为管理员凭据，管理员登录也不应交给玩家。

顶部“创建新房间”填写房间/对局名称（1–80字符）、游戏、场景、人数及每次行动时限（1–3600秒，默认600）。参与方式可选“允许人类加入（大厅）”“仅通过邀请加入”或“Agent 直接开局”。开放大厅的房间也可邀请 Agent，与人类一起准备和参赛。创建房间不会自动占座；房主复制各席位的 seat token 单独发放，玩家点击房间并输入密钥入席；人类客户端自动确认当前完整成员表，由房主或创建者开始。等待时可“离开房间”释放席位；“断开”保留席位用于恢复。Agent 直接开局会立即发牌和计时。

大厅每5秒刷新，只显示开放、未过期且有空位的兼容房间；满员或开始后的旧列表点击由服务器拒绝。旧服务不支持新参数时会显示错误，客户端不会自动重试创建。房间名称随开局保存，在大厅、参赛页、对局记录和回放标题展示；旧记录回退显示游戏名称。

更新按钮查询公开仓库 Releases，按当前操作系统和架构下载并核对摘要，不携带游戏凭据。历史0.9.0含后端安装包已移入私有历史仓库，新公开版本从0.9.1开始。

回放展示服务端已保存动作、本席可见信息以及客户端上传记录。没有模型 messages 时应显示缺失，工具日志不等于完整思考。附件按需下载，不在界面执行上传的 HTML。

房主可在房间页看到实时成员和灰色/可点击的开始按钮，等待状态使用普通鼠标指针。管理房间可重新发放空席密钥，已入席密钥不变。游戏进行中也能从回放区进入回放（仍遵守账号权限）。
