# Coop Bench 0.7.1 · Windows / macOS 远程客户端

## 方案与边界

0.5.0 使用 **Electron 桌面客户端 + 远程 HTTPS API**，新增设置面板和账户密码登录。界面随安装包分发，直接复用对局选择、回放、模型消息、附件和审阅功能。默认启动不会运行本机游戏服务器或创建本机游戏数据库；对局状态与轨迹继续由后端保存。

```text
Windows / macOS 客户端
  本地打包界面 → 受限主进程 API 桥接 ── HTTPS ── 后端 API → SQLite / 轨迹附件
                                                   ↑
                      各地 Agent ── 独立座位凭证 ──┘
```

Electron 适合本项目，因为现有审计页面和 Node.js 本地引擎都能复用，Windows 与 macOS 使用同一套界面。代价是安装包包含 Chromium，体积较大。默认远程模式只加载随包分发的界面，服务器不向桌面提供可执行页面代码。

当前后端注册 **10 个游戏适配器**。这表示表列范围能创建和行动，不表示实现了所有原版战役、扩展或关卡；完整范围见 [README 游戏表](../README.md#能玩哪些范围)。

## 一屏回放（0.6.0）

选择对局后，默认并排显示各玩家的手牌、合法可见信息、当步或最近一次的决策与行动；下方固定时间线。当前行动者高亮，非行动者的上次决策会标明步号。三人场景在 1280×800 与 1440×900 窗口无需滚动整页；长思考原文点击单独展开。对局列表、创建对局、完整技术证据均在顶部按钮中。

花火牌面标为人类审计视角，玩家自己实际知道的提示另列；完整 reasoning 只有运行器确实上传且能精确关联时才展示，否则显示已有简述与缺失状态。见 [更新和验证](release-0.6.0.md)。

## 首次连接

**默认云端入口为 `https://coop.neutrinophysics.cn:34935/api/v1`。** 2026-09-18 已验证该入口的个人凭证认证与历史轨迹读取，0.5.0 账户接口也已部署；截至 2026-09-18 13:58，owner 已成功设置密码；当前状态以账户接口为准，不要重置。旧 0.4.1 客户端默认值为 443，新设备须改为上述地址。[部署说明](cloud-api34935.md)、[0.5.0 发布验证](release-0.5.0.md)

1. 打开客户端，通过右上角「设置」检查后端地址。默认登录方式为用户名与密码；用户名初始填入 `owner`，使用组织者分配的实际账户。
2. 首次没有账户密码时，切换到「个人凭证」，输入组织者单独提供的 **人工 API 访问凭证** 并连接。然后进入「设置」，填写并确认新密码。未经个人凭证认证，不能匿名抢先设置密码。
3. 设置后使用用户名与密码登录；修改已有密码时须填写当前密码。新密码须为 12–128 个 Unicode 字符、UTF-8 不超过 512 字节，不能为空白。密码不写入 URL、日志、剪贴板或应用配置，提交和关闭设置面板后清空密码输入框。
4. 可选勾选「记住登录」。不勾选时，登录会话仅驻留本次应用进程内存；勾选后使用系统加密能力保存会话，**不保存账户密码**。系统无法提供安全存储时不能降级为明文保存。修改该选项在下一次登录或成功设置密码时生效。
5. 连接后可浏览服务器已保存的对局，切换玩家视角，审计动作、沟通、模型 messages、附件及审阅笔记。

「设置」同时显示当前账户、角色、密码是否已配置、登录方式与会话到期时间，并提供检查连接按钮。新地址只有身份验证成功后才显示绿灯。旧服务器不支持账户接口时，继续使用个人凭证登录；个人凭证不是 SSH 密码、网站 Basic Auth 密码或玩家座位凭证。

支持远程 HTTPS 地址；HTTP 仅供 `localhost`、`127.0.0.1` 或 IPv6 loopback 的本机开发端点使用。不会通过更换端口或关闭证书校验绕过 HTTPS。API 地址可配置，但只能使用桥接允许的 API 路由和操作。

客户端主进程持有已登录人工凭证或账户会话，并附加到授权请求。远程模式的页面脚本只获取连接状态、身份和响应数据，`getConnection()` 不返回明文凭证。退出会取消未完成请求，清除当前页面中的轨迹、座位配置和记住的登录状态，并尝试撤销当前服务器会话；服务器不可达时明确提示撤销未确认。设置或修改密码会替换当前会话，并使此前的密码会话失效。切换连接或更新密码后，旧请求返回的结果不会写入新会话。

## 连接状态与诊断

页面顶部常驻状态栏，同时显示颜色与文字、实际 API 地址、失败原因及最后检查时间：

| 状态 | 含义 |
|---|---|
| 灰灯「未连接」 | 尚未登录或已退出 |
| 黄灯「连接中 / 检查中」 | 正在恢复连接、登录或手动验证身份；连接按钮禁用，防止重复提交 |
| 绿灯「已连接」 | 当前会话的 `/identity` 已成功返回有效身份 |
| 红灯「连接失败 / 连接已断开」 | 网络、TLS、代理或 API 响应失败；不据此判断密码错误 |
| 红灯「凭证失效」 | API 返回身份认证失败，当前凭证与页面缓存已清除 |
| 灰灯「新地址未验证」 | 修改了地址输入框但尚未连接；状态栏注明仍在使用的原地址 |

身份心跳每 20 秒执行一次，不依赖“自动刷新对局”复选框；「检查连接」按钮可立即验证。状态表达最近一次检查结果，系统休眠或离线期间无法保证即时检测。普通业务 400 / 403 / 409（例如无权执行某操作）不会被误判为断网；身份检查失败、5xx 和返回网页的假 API 响应会标红。退出或切换服务器后，旧请求无法改变新会话的状态灯。

错误说明分别识别域名解析、端口拒绝连接、HTTPS 握手 / 证书、超时、代理 Basic Auth 和 API 凭证拒绝。代理要求网站密码时，客户端明确说明尚未验证 API 凭证；不会尝试把一种密码当作另一种凭证。主进程通过脱敏的结构化错误向页面传递分类，保留原因并隐藏原始异常与服务端响应正文。

历史只读诊断（2026-09-17 21:49 北京时间）：当时已安装客户端仍使用 443，443 与 34935 均未监听；服务器内 API 与 owner 身份验证正常。因此当时的连接失败发生在认证之前，不能据此判断用户密码错误。34935 随后已启用，历史诊断不代表当前状态。[脱敏诊断证据](../artifacts/client-connection-diagnosis.json)。

## 创建对局与接入 Agent

具备 `operator` 或本机 `coordinator` 权限时，审计台显示创建区：

1. 选择游戏、官方场景 / 关卡和人数，展开查看该游戏的规则摘要与实现遗漏。
2. 点击“创建对局”。客户端在创建请求完成前禁用重复提交；不自动重试结果不明的创建请求。
3. 为每个玩家分别复制连接配置，只交给对应的 Agent：

```json
{
  "baseUrl": "https://coop.neutrinophysics.cn:34935/api/v1",
  "episodeId": "创建后返回的对局 ID",
  "seatToken": "仅此玩家的座位凭证"
}
```

玩家座位凭证只在创建响应中返回。关闭或清除配置前应完成分发；不要给 Agent 人工审计凭证，也不要把其他玩家的配置一起交给它。各个 Agent 可在不同机器上直接访问同一个 API；客户端关闭不会停止远程游戏服务。

`auditor` 不能创建或结束对局，只能查看已结束记录并写审阅笔记。桌面远程客户端不提供玩家动作调试入口，避免人工凭证和玩家凭证混用。原浏览器 `/play` 调试页保留在本地模式中。

创建期间如果网络中断，服务器可能已创建成功而客户端未收到座位配置。先刷新对局列表确认结果，再决定是否新建；当前创建接口没有可恢复首次座位凭证的幂等收据。

## 轨迹、消息与附件

- 状态、合法沟通、动作、各玩家观察与计分由服务器保存；客户端提供时间线与玩家视角回放。
- 比赛中的模型消息需运行器通过 [messages API](agent-messages.md) 上传。真实 reasoning、简短决策说明、token 计数及未提供内容分别标注，客户端不会补造模型隐藏思考。
- [原始附件](agent-artifacts.md) 从 API 下载，客户端校验字节数和 SHA-256 后导出。附件仅作为数据保存，不执行其中的代码。
- 审阅笔记写回服务器；应用关闭后仍保留。远程服务器的备份与长期保存策略不由客户端关闭或卸载控制。

## 备案与当前服务器

当前方案继续使用现有北京服务器，在完成备案后使用 `coop.neutrinophysics.cn` 提供后端 API。桌面界面本地化不会让中国大陆服务器上的域名 API 自动免于备案；改用 `8080`、`8443` 等端口也不能替代 ICP 备案。腾讯云的说明明确指出，是否需要备案取决于托管场景，而非是否使用 80 端口。参见 [腾讯云：是否需要备案](https://cloud.tencent.com/document/api/243/19630)。

客户端实现与服务器域名可用性是两件事：即使安装包能启动，未备案拦截仍可能导致远程 API 无法连接。备案流程完成前，不应把客户端打包完成描述为当前公网 API 已恢复可用。

## 开发、安装目标与本地模式

独立仓库为 [neutralino-ai/coop-bench](https://github.com/neutralino-ai/coop-bench)，只需克隆该仓库，无需相邻项目。开发使用 Node.js 24.21.0 与 pnpm 11.19.0；安装包用户不需要另外安装 Node.js。[新电脑开发指南](development.md)

```text
pnpm install --frozen-lockfile
pnpm desktop          # 默认远程客户端
pnpm desktop:local    # 保留单机引擎与 loopback HTTP API
pnpm dist:win         # Windows x64 NSIS 构建
pnpm dist:mac         # macOS Intel / Apple Silicon DMG、ZIP 构建
```

已打包程序也可使用 `--local` 启动保留的单机模式。本机模式由应用运行规则引擎、SQLite 和 loopback API；关闭应用会停止这一本机服务。0.3.0 的历史产物和验证结果见 [单机应用文档](local-app.md)。

## 检查更新（0.7.1 起）

打开“设置 → 检查更新”。客户端匿名访问公开仓库的最新正式 Release，根据 Windows x64、Mac Intel 或 Apple Silicon 选择安装包。下载完成且大小 / SHA-256 一致后，点击“打开安装程序”。Mac 打开 DMG 后按系统提示替换应用；Windows 按安装向导升级。旧版本没有这个按钮，第一次需手动安装新版本。

代码公开不代表游戏 API 匿名开放；API 仍需个人账号或独立 Agent 座位凭证。更新请求不会携带这些凭证。未签名安装器 / 未公证 Mac 应用仍受系统安全策略检查，校验摘要不是开发者代码签名。

顶部“游戏规则”可切换 10 款游戏，查看规则概要、支持场景、实现范围和来源。花火显示全队“剩余提示 x / 8”，对应回放所选时点；提示消耗 1，弃牌或成功打出 5 恢复 1，最多 8。

密码输入可临时显示，并提醒 Caps Lock、首尾空格、全角字符。空格与字符大小写保持原样，不会被自动修正。登录报错明确区分“服务器认证拒绝”和 DNS / TLS / 端口等网络失败。不要把密码发到聊天或工单。

0.7.0 已知问题：远程模式的 Electron 网络库会拒绝 GitHub 下载重定向，需手动升级 0.7.1；补丁使用 Node fetch 并保留下载校验。
