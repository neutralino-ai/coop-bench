# Agent 理由、轨迹与统一回放

## 核对结论

- 桌面 `MinimalModelAgent` 与 iOS `ModelAgent` 的动作工具要求 `decisionSummary`，运行时校验非空、长度不超过 1200、含中文；缺失或格式错误让模型修正，不直接提交。人类动作仍可不填理由。
- Coding Agent 直接 HTTP/MCP 的服务端契约仍将理由列为可选；文档要求 Agent 必填，不构成对每次调用的硬性保证。本次没有逐局审计历史动作，也没有更改共享服务端契约。
- 内置运行器记录真实请求/响应和工具往来，终局尝试上传与封存。桌面核对每条回执和封存范围/末序号；iOS 核对消息和封存末序号。失败保留本地队列供恢复。已结束游戏不等于已收齐轨迹，封存也不等于所有模型内部思考可得。
- 外部 Coding Agent 的完整宿主日志需要自行导出和上传；MCP/工具记录器只能保证其实际观测到的范围。隐藏思考缺失时不补造。

## 修复

此前回放只解析 `/messages`；赛后上传的 Coding Agent 原始 transcript 附件只提供下载，所以已经上传也可能一直显示理由。

- 终局回放读取已完成的 `agent-trace` 附件，复用有长度上限、会话取消、字节数及 SHA-256 校验的下载路径。支持 JSON/JSONL 显式消息、Codex response_item 与 Claude message/content blocks；已知格式按实际内容解析，未知/损坏格式保留理由并显示错误。
- 每席优先最新可识别附件；无附件时使用原消息流；仅工具轨迹也可展示。有轨迹时替换独立理由与动作区。原始附件仍可下载。终局页面定期检查后续上传，失败可手动重试。
- System 独立为灰蓝色，保留 User 蓝、Assistant 紫、Thinking 黄、Tool use 橙、Tool result 绿。类型/时间/详情同一行，默认 1–2 行预览；关联本轮的 Tool use 继续高亮。没有将全部消息称为完整思考。
- 删除独立“输入审计 → 实际模型请求”窗口及其读取循环、导航和测试；保留服务器原始 observation 审计。房间管理没有轨迹入口，保持席位与内置 Agent 运行/恢复状态。
- 轨迹收集状态分别显示消息封存和已上传附件，避免把“消息流为空”误解为“未上传附件”。
- 复制给 Coding Agent 的提示词补充行动回执、终局上传、脱敏、缺失类别说明及上传确认要求。
- 上传脚本现在校验新上传与重复上传的 complete 回执，确认长度和 SHA-256 与原文件一致。旧实现只返回完成请求结果，缺少客户端的最终核对。
