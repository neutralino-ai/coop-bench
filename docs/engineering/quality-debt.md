# 质量债及完成标准

本轮提供可持续的工程基线，不能据此宣布整套系统获得“工业级认证”。问题必须通过需求和检查关闭，不靠调整阈值消失。

| 优先级 | 范围 | 完成标准 |
|---|---|---|
| P1 | client/runtime、seat-session、desktop/remote-session 的严格类型 | 外部 JSON/schema、内部类型和失败/重试/恢复测试齐全；每次迁移缩小未检查范围 |
| P1 | WKWebView/Electron IPC 与真实 iPhone 回归 | 席位隔离、凭据生命周期、恶意输入与断线恢复有可重复证据；独立审阅不能由本次自检代替 |
| P2 | web 的共享 classic-script 依赖与视图模块化 | 分模块改动，真实入口回归通过，避免整页重写破坏信息密度和历史 |
| P2 | 未使用变量检查及代码可读性 | 分模块启用 no-unused-vars；只格式化所改逻辑，保持 diff 可评审 |
| P2 | 性能/覆盖率预算 | 以大历史/大轨迹合成场景建立可测基线，再评审阈值；不凭空承诺 100% |

初次全量 checkJs+strict 的诊断为 3,365（未标注类型、DOM/bridge 声明等混合），不是 3,365 个已确认运行时缺陷。目前不能将 lint 通过称为完整类型安全。已严格覆盖协议和发布来源，新模块必须严格类型；现有模块按上述顺序迁移。
