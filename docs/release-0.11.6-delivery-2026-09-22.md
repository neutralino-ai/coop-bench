# 0.11.6 自动刷新与 Agent 恢复核验

回放原先有两套每5秒刷新的入口，牌局详情、各席轨迹、收集状态和输入审计分别读取，却共用服务端同一账号的重读取额度。轨迹自身的节流没有覆盖其他读取，叠加后触发 RATE_LIMITED。

本次将审计 GET 统一到传输层的公平队列：初始3次，每3.5秒补1次，牌局、轨迹、观测和导出共用；429 的 Retry-After 同步暂停其他审计读取。长等待保持额度暂停并交给后续刷新，不提前重试；切换账号或取消请求会丢弃旧队列。身份检查和行动提交不排入审计队列，POST 不自动重试。限流不再把已验证连接误报为断线，也不会把原有断线状态变绿。倒计时校时使用实际发送时刻，排队时间不算网络往返时间。

回放只保留专用刷新入口，退出回放后不会继续读取隐藏牌局。仍读取未伴随新动作的轨迹消息，保留本地倒计时、五色紧凑卡和原始详情。未改变服务器限流策略，未部署或重启后端，未中断真实对局。

内置 Agent 原有恢复行为经过代码和回归测试核验：游戏连接暂时中断会重试；桌面程序重启后，可从“我创建的 → 管理房间 → 恢复 Agent”恢复原席位。系统加密存储保存席位元数据，运行器磁盘存储保存模型历史和未确认动作的原幂等键。iOS 保存模型配置后会在登录/回前台时尝试恢复；未保存密钥或本地数据丢失时不能承诺自动恢复。模型服务耗尽有限重试后会停止，需人工恢复。离线期间服务端行动时限继续，可能执行默认动作或结束对局，不能恢复已结束的局。

本地新增并发读取预算、取消/换账号、共享长冷却、连接灯状态、隐藏回放不刷新，以及重新构建 Agent 管理器后从磁盘恢复原席位/模型历史/待确认动作测试。后者验证持久化重开，不冒充真实进程崩溃或实体设备验收。整套包内验收使用真实节流，测试总时限由90秒增加为240秒，不绕过读取预算。

0.11.6 候选提交 `3399228`，CI `35703094668`：本地116项单元、Windows实际包126项通过，CI开发包和iOS模拟器通过。但Windows最终包的附件验收仍用18秒等待，合法的排队加5秒Retry-After可超过18秒，因此任务在下载完成前失败。已取消未完成流水线，未公开Release。后续0.11.7增加明确覆盖19秒合法下载的回归，并将该项验收等待设为40秒；不改写原标签，也不绕过产品节流。
