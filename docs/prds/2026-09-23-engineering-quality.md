# 可追溯开发与持续质量检查

Status: implemented

## Problem

用户发现服务端长期积压未提交代码；部署包与可检出的 Git 提交脱节。客户端也有旧分支遗留工作，入口文档混入历史规则。现有测试不能覆盖未接入的静态检查和发布来源问题。

## Scope

恢复历史修改、理清仓库边界、落地需求/决策/交付流程与 CI、严格检查后端和客户端关键协议、拦截脏树发布。此改造不自动部署或发布新版本，不重写游戏规则、不删除旧工作或真实实验记录；完整前端类型迁移和整套安全审计是显式技术债。

## Acceptance criteria

- 原未提交内容可通过恢复提交和私有字节快照找回；main 的新变化有明确提交与验证。
- AGENTS/CLAUDE 只有一致的当前规则；PRD 有验收、验证、回滚；链接和状态可校验。
- 全量自有代码 lint 无错误/警告；关键席位协议严格类型检查通过，其他 JS 类型覆盖边界明确；禁止新增 any/检查禁用。
- 单元、四平台 CI 与公开包边界检查通过；失败/跳过如实记录。
- 脏树/未跟踪源码不能生成部署包；制品有 commit/tree；合并前远端检查通过。

## Validation

执行证据在 [整改交付](../engineering/quality-delivery-2026-09-23.md)，按实际检查结果更新状态。

## Rollout and rollback

代码经 PR 合并 main；普通开发构建继续可用。新打包约束只影响未来制品，既有部署及历史 build 不改写。回退用 revert 相关整改提交，保留恢复提交和历史记录；不得靠放行脏树回避质量失败。生产部署仍另验授权与活动局。
