# PRD 规则

非平凡新功能、跨端 API、持久化/权限或发布流程变更创建 YYYY-MM-DD-topic.md。状态只有 proposed、in-progress、implemented、rejected；已完成记录必须附实际验证及限制，不能留未来时态冒充完成。小修复可以在 PR 正文表达，不为每个按钮制造文档。

复制 [模板](TEMPLATE.md)。Problem 描述用户问题；Scope 写范围和非目标；Acceptance criteria 用可观察结果；Validation 对应检查和证据；Rollout and rollback 写兼容、数据保护和回退。长期架构取舍单独写 docs/decisions，交付日志单独写 docs/*delivery*。
