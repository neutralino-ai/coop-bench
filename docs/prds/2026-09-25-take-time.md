# Take Time creation, play and replay

Status: implemented

## Problem

Take Time currently falls back to raw JSON while Hanabi has a readable player board. Add catalog-driven clock selection and options, a compact six-sector board with rules, public backs, own hand, discussion and direct placement controls, and the same recorded-board renderer in replay. Human and built-in model seats retain the existing runtime, reason, trace and recovery contract. The server owns legality and results; the public client contains no engine or private source material.

## Scope

Shared web views used by desktop and iOS, and existing human/model runtimes. No private game implementation or scanned publisher artwork in the public repository.

## Acceptance criteria

- Select any server-offered clock and preview its conditions; configure retry bonus and Rebirth before creation.
- Display stable seat order, own legal hand, current actor, pointer, rotation, second-hand restrictions and current face-up allowance.
- Human controls submit only current API legal actions with observation identity; discussion ends after looking.
- Agent reasons and actual model traces remain private audit evidence in existing replay; no future reveal fills historical frames.
- Desktop and narrow-screen rendering is usable, including empty hand, waiting, terminal and error states.

## Validation

Behavior tests of rendering and submission, existing runtime/replay regression tests, lint/typecheck, shared-web/iOS asset builds, and real browser rendering at desktop and phone widths. Native packaging and physical-device acceptance require later release validation.

Acceptance evidence: [implementation and validation](../engineering/take-time-delivery-2026-09-25.md).

## Rollout and rollback

Capability-driven options work with old servers. New rendering tolerates old observations. No release/deployment is part of this task; rollback to the previous client leaves saved games intact.
