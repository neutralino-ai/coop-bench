# Coop Bench 安全审计与修复记录

日期：2026-09-17。范围：本仓库的 HTTP API、rollout 审计前端、Electron 权限边界，以及供四名同事测试的访问控制。

## 结论与边界

已在一次性本机实例中复现输入复杂度缺陷，并对越权、伪造请求头、路径探测和 HTTP 解析歧义执行了有界回归测试。这些本地攻击回归使用 `127.0.0.1` 随机端口、内存 SQLite 和专用假凭证；没有对既有真实 rollout 进行攻击、删改或压力测试。后续云端部署验收另外创建了一局明确标记的机械策略测试，范围见下文。

这些测试能证明列出的攻击样例受到限制，不能证明不存在其他漏洞，也不能替代实际部署后的网络边界检查。没有进行公网扫描、长时间慢连接攻击、饱和流量攻击或第三方系统测试。

计划中的公网攻击检查子任务因平台风控拦截而未执行，不能记为“公网渗透测试通过”。

| --- | --- | --- |
| 小体积深层 JSON 可触发递归异常 | 合法 seat 向 `/actions` 提交 14,012 字节、7,000 层数组，返回 HTTP 500 `INTERNAL`。随后健康检查 200，未观察到进程退出。 | HTTP 层在调用引擎前迭代检查 JSON，深度上限 32、节点上限 8,192，原样例改为 413；回归通过。不能把原问题描述成已复现远程代码执行或进程崩溃。 |

## 安全机制

- Node 上游仍只绑定 `127.0.0.1`。本机没有为桌游添加入站放行；独立云实例的 HTTPS 入口由反向代理提供。
- JSON 除了字节上限，还限制深度、节点数，拒绝无效 UTF-8、无限数值和保留对象键；不支持压缩请求体。
- HTTP 请求头最多 8 KiB；最多 64 个连接；请求、闲置连接和 keep-alive 均有时间限制。
- HTTP 使用总量、凭证和高成本操作预算。超限返回 429；这些预算用于小组测试，不能抵御链路带宽被打满。
- SQLite 事务内限制单局及全局持久化内容，命令、观察、事件和注释均有数量/字节配额。字节配额统计 UTF-8 内容，不能等同于 SQLite 索引、页面及 WAL 文件的实际磁盘上限；仍需监控剩余磁盘空间。
- HTML 增加 CSP 的 `object-src`、`base-uri`、`form-action`；禁止嵌入 iframe；不缓存凭证相关响应。
- 安全日志记录固定 endpoint 分类、状态、时间和已认证身份；不记录 bearer、完整 URL、请求体或玩家手牌。日志轮转限制体积。
- Electron 源码保持 sandbox、contextIsolation 开启，nodeIntegration 关闭；IPC 检查发送窗口、主 frame 与页面来源；拒绝外站导航、新窗口和权限申请。与 [Electron 官方安全清单](https://www.electronjs.org/docs/latest/tutorial/security) 的相关要求一致。

默认预算如下；这些是服务资源策略，不是官方桌游规则：

| 范围 | 默认上限 |
| --- | --- |
| HTTP 全服务 | 突发 200 次，随后按每分钟 600 次补充 |
| HTTP 每个凭证 | 突发 60 次，随后按每分钟 180 次补充 |
| HTTP 每个凭证的高成本操作 | 突发 8 次，随后按每分钟 20 次补充；覆盖创建、完整 rollout、审计/训练导出与重放 |
| 保存的对局 / 同时进行中的对局 | 1,000 / 32 |
| 每局命令 / 事件 | 1,000 / 2,500；拒绝的命令也计入 |
| 每座位不同的观察 | 2,000；相同观察复用记录 |
| 持久化业务内容 | 每局 64 MiB，全服务 512 MiB |
| 审计备注 | 每局 100 条、每座位 20 条反思、每局合计 256 KiB 文本 |

资源超限返回 `RESOURCE_LIMIT`，整次新增写入回滚；原幂等回执仍可读取。协调者可追加一个终止标记，将实验标为 `truncated`，该终止操作有预算例外。不会自动将超限记为团队失败。HTTP 限流返回 `RATE_LIMITED`；等待可以补充请求预算，持久化配额则需要整理数据或由主机所有者调整配置。

角色、配置入口与观察语义见 [已实现 API](runtime-api.md)。腾讯云部署见 [独立云主机部署说明](cloud-deployment.md)，私有组网备选见 [四人共享说明](private-sharing.md)。修改默认预算后需要重跑相关测试。

## 部署复核重点

同事没有固定公网 IP，公网 IP 白名单不适合作为主要身份控制。用户后续选择了独立腾讯云部署：使用 HTTPS 与逐人应用凭证，应用上游仍监听 loopback；私有组网保留为备选方案。公网 IP 改变不应要求修改应用身份权限。

所有 API 前缀都应受到相同权限限制。云端 HTTPS 入口可公开，但特权操作必须有独立凭证；私有组网入口额外拒绝未获网络授权的设备。不要把 X-Forwarded-For 或身份头当作应用鉴权依据。Host 只能用于请求来源约束，不能单独证明请求来自本机用户；启用共享时，整个 HTTP 服务都禁止 coordinator 主凭证，包括 localhost 地址。

首次部署曾通过有效个人凭据登录、轨迹展示和注销的正常浏览器验收；最新 Windows 网络复验失败见上文。公网恶意/无效凭据及撤销后的端到端攻击式验收未执行，不能用本机回归或 SSH 内测试替代。8788 仅监听服务器 loopback，Lighthouse 防火墙也未为它添加规则；这两项是配置证据，不冒充公网扫描结果。若以后启用私有组网，还需验证未获网络授权的设备无法连接入口。

本机 Windows 防火墙、Defender、Node 入站规则收紧与 ToDesk 保留情况另见 [Windows 安全检查](windows-security-check.md)。
