# Coop Bench 0.9.4

修复内置 Agent 因 DeepSeek 思考模式参数不兼容而停在第一步的问题，并在加入席位前验证模型是否可用。

- 默认地址 `https://api.deepseek.com`，默认模型 `deepseek-flash`，内置 Agent 使用 Responses API。已有命令行 Chat Completions 接入仍兼容，省略不受支持的强制 `tool_choice`。
- 点击“测试连接与工具调用”，实际验证两轮工具调用及回执；只有成功后才能加入席位。测试失败不会占用席位。测试可能产生少量模型费用。
- API key 默认用系统安全存储加密后保存在本机，下次可留空复用；提供清除按钮。保存值按账号、游戏服务和模型 API 地址绑定，不向界面返回明文，也不会随编辑后的模型地址发送。
- Responses 每轮发送完整可见历史，保留实际 reasoning、工具调用 ID 和动作回执；原始请求与响应完整记录，回放可显示 Responses 的 reasoning 原文。
- 每次模型请求最多 60 秒；网络/限流/服务端临时错误最多重试一次。单次决策最多 120 秒，且不超过服务端剩余期限。空输出或无效工具格式最多两次尝试，必需行动回合不能以 wait 代替动作。
- 持续失败会停止自动模型调用，在开局后的房主页面显示具体原因。原有席位、回合时限和游戏结果仍由服务端管理。

验证：90 项客户端自动测试；覆盖连续两轮 Responses、验证失败不占席、加密密钥复用及地址隔离、超时与重试上限、无效输出停止、错误分类和回放 reasoning。Windows 与 Mac 两架构均由 CI 执行实际包内管理端和 Player 验收、公开包边界检查，全通过后发布。

模型协议回归使用本机合成提供方；本次定位依据实际对局上传的 DeepSeek 错误记录，未使用真实 DeepSeek API key 完成修复后的实局。Mac CI 不代替实机安装验收。
